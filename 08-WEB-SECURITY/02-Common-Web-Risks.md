
# 08-02｜常見 Web 風險與防護

## 本課目標
從原理理解常見 Web 漏洞，知道它們為什麼發生，以及開發者如何防護。初學階段不對真實網站測試。

## 1. SQL Injection（SQL 注入）
成因：應用程式把使用者輸入不安全地拼接進資料庫查詢，讓輸入被當成 SQL 指令的一部分。
可能影響：未授權讀取或修改資料，取決於應用程式和資料庫權限。
防護：使用參數化查詢、限制資料庫帳號權限、不依賴單純字串過濾、妥善處理錯誤訊息。

## 2. XSS（跨站腳本）
成因：網站把不可信資料當成可執行的瀏覽器程式碼呈現。
可能影響：在使用者瀏覽器中執行非預期腳本。
防護：依輸出情境編碼、使用安全 DOM API、適當部署 CSP，避免不安全插入 HTML。

## 3. Broken Access Control（存取控制失效）
成因：伺服器沒有在敏感操作中正確檢查使用者權限。
可能影響：使用者讀取或修改不屬於自己的資料。
防護：伺服器端逐次檢查權限、採用預設拒絕策略、記錄重要操作。

## 4. Authentication Failures（身分驗證失效）
可能原因包括密碼政策薄弱、工作階段管理不安全、多因素驗證缺失或帳號恢復流程設計不當。
防護包括安全密碼儲存、多因素驗證、登入限制和安全 Session 管理。

## 5. 專業測試不只找問題
還需要描述條件、保存可重現證據、評估影響、提出修復方式，並在修復後重新驗證。
