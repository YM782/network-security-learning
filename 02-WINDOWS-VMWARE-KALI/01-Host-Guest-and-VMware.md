## 二、先理解三個核心名詞

### 1. Host：宿主機

Host 是實際安裝 VMware 的實體電腦。以常見的學習環境來說，Windows 就是 Host。

Windows 負責管理實體 CPU、實體記憶體、SSD、顯示卡、鍵盤、滑鼠和實體網卡。VMware 是在 Windows 上執行的應用程式。

### 2. Guest：客體系統

Guest 是安裝在虛擬機裡的作業系統，例如 Kali Linux。

Kali 看到的是 VMware 提供的虛擬硬體。它可能認為自己有一顆虛擬硬碟、一張虛擬網卡和若干虛擬 CPU，但這些資源最終仍由實體電腦提供。

### 3. Hypervisor：虛擬機監控程式

Hypervisor 負責建立和管理虛擬機，協調 Guest 與實體硬體之間的資源使用。

常見分類：
- Type 1：直接運行於硬體之上，常見於伺服器虛擬化環境。
- Type 2：作為一般作業系統上的應用程式運行。桌面版 VMware Workstation 通常屬於這類使用方式。

不需要先背所有虛擬化產品的分類，先理解 VMware 在 Windows 裡管理虛擬機即可。

## 三、Windows 和 Kali 如何共享實體資源？

### 1. CPU

VMware 會把部分 CPU 執行資源提供給 Kali。虛擬機設定中的處理器數量，是 Guest 可使用的虛擬處理器配置，不代表電腦真的多出一顆實體 CPU。

如果 Windows、Chrome 和 Kali 同時執行大量工作，它們會競爭實體 CPU 時間。

### 2. RAM

Kali 需要記憶體執行核心、桌面環境、終端機和工具。VMware 會根據配置和實際需求使用宿主機記憶體。

配置原則：
- 不要把全部實體 RAM 都分配給 Kali。
- 要為 Windows、Chrome 和背景服務保留足夠記憶體。
- 先以能正常啟動桌面和完成基礎練習為目標。
- 如果 Windows 明顯變慢，先正常關閉 Guest，再觀察資源變化。

### 3. 虛擬硬碟

Kali 裡看到的磁碟通常不是另一顆實體 SSD，而是 Windows 硬碟上的虛擬磁碟檔案，例如 VMDK。

VMware 把虛擬磁碟呈現給 Guest 使用；Guest 讀寫虛擬磁碟時，最終仍會在 Windows 所在的實體儲存裝置上產生 I/O。

**重要：** 不要在 Windows 檔案總管裡直接刪除、移動或重新命名正在使用的 VMDK 檔案。這可能令虛擬機無法啟動或造成資料損壞。

### 4. 虛擬網卡

Kali 裡的網卡是 VMware 提供的虛擬網路介面。它可以連接到 NAT、Host-only 或 Bridged 等虛擬網路模式。下一課會詳細說明。

## 四、虛擬機資料夾裡通常有什麼？

常見檔案可能包括：

| 檔案類型 | 常見用途 |
|---|---|
| .vmx | 虛擬機設定檔 |
| .vmdk | 虛擬硬碟資料或描述檔 |
| .nvram | 虛擬韌體相關狀態 |
| .vmsd | 快照中繼資料 |
| .vmsn | 快照狀態資料（依快照類型而異） |
| .log | 虛擬機運行記錄 |

實際檔案名稱和數量會依 VMware 版本、虛擬機設定和快照狀態不同。

不要把副檔名當成刪除依據。尤其 VMDK 可能包含整個 Kali 系統和實驗資料。

## 五、Snapshot、Clone 和 Backup 有什麼不同？

### 1. Snapshot（快照）

快照記錄虛擬機在某個時間點的狀態，讓你在實驗出錯後有機會回到先前狀態。

適合：
- 修改 Kali 設定前。
- 安裝大型工具前。
- 開始一個可能破壞系統的授權實驗前。

限制：
- 快照會占用磁碟空間。
- 快照可能形成依賴鏈。
- 快照不是獨立、完整、可長期保存的備份。
- 虛擬機所在實體硬碟故障時，快照也可能一起遺失。

### 2. Clone（複製）

Clone 是建立另一份虛擬機副本。完整複製通常會占用更多儲存空間；連結複製可能依賴原始虛擬機。

適合建立實驗副本，但要注意網路識別、主機名稱和 IP 衝突。

### 3. Backup（備份）

備份是把重要虛擬機資料另行保存到其他儲存位置，並確認日後可以還原。

真正重要的實驗報告、程式碼和個人文件應另外備份，不要只依賴快照。

## 六、實驗 A：查看虛擬機設定（只查看，不修改）

1. 關閉 Kali 虛擬機，避免在運行中修改硬體設定。
2. 在 VMware 主畫面選擇 Kali。
3. 打開虛擬機設定（通常是 Edit virtual machine settings）。
4. 依次查看 Memory、Processors、Hard Disk 和 Network Adapter。

## 七、實驗 B：在 Kali 內確認系統看到的資源

啟動 Kali，開啟 Terminal，逐條執行：

### 1. 查看 CPU 資訊

    lscpu

用途：顯示 CPU 架構、處理器數量、核心和執行緒等資訊。

### 2. 查看記憶體

    free -h

用途：查看記憶體總量、使用量、可用量和 Swap。-h 代表使用較容易閱讀的單位。

### 3. 查看磁碟和檔案系統

    lsblk
    df -h

lsblk 顯示區塊裝置；df -h 顯示已掛載檔案系統的容量使用狀態。兩者用途不同。

### 4. 查看網路介面

    ip addr

用途：查看網路介面、狀態和 IP 位址。

## 八、常見故障與排查

**問題 1：Kali 啟動後 Windows 很慢。**

可能原因：Guest 分配過多記憶體、Windows 同時運行大型程式、虛擬磁碟 I/O 很高，或 CPU 長時間忙碌。

排查：先記錄 Windows 工作管理員資源使用；正常關閉 Kali；比較關閉前後差異。不要一開始就同時修改 CPU、RAM 和磁碟設定。

**問題 2：虛擬機提示找不到磁碟。**

可能原因：VMDK 被移動、刪除、改名，或虛擬機設定中的路徑失效。

排查：先不要建立新磁碟覆蓋原資料；確認原始虛擬機資料夾是否還在；保存錯誤訊息，再檢查 VMX 指向的磁碟路徑。

**問題 3：快照占用太多空間。**

原因：快照可能保留建立快照後的變更資料。不要直接刪除快照相關檔案；應透過 VMware 的快照管理功能檢查和整理。

**問題 4：Kali 裡看不到預期的硬體名稱。**

原因：Guest 看到的是虛擬硬體，名稱和實體 Windows 硬體可能不同。這不代表實體設備消失。
