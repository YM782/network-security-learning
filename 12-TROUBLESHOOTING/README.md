
# 12 — 初學者故障排查手冊

## 排查原則

遇到問題時，先不要連續亂改設定。依序做：

1. 記錄完整錯誤訊息。
2. 確認目前在哪個系統和視窗。
3. 確認命令有沒有打錯。
4. 查看網路、權限和磁碟等基本狀態。
5. 一次只改一個地方。
6. 修改前先建立快照或備份。
7. 修復後再次驗證。

## 問題 1：Kali 沒有網路

先執行：

```bash
ip addr
ip route
ping -c 4 127.0.0.1
ping -c 4 1.1.1.1
nslookup example.com
```

判斷方向：

- 沒有網卡或沒有 IP：先看 VMware 虛擬網卡是否連線。
- 有 IP，但沒有預設路由：檢查 VMware 網路模式和 DHCP。
- 能連 IP，不能解析網域：檢查 DNS。
- ping 沒回應不一定表示整個網路故障，因為有些設備會封鎖 ICMP。

## 問題 2：顯示 command not found

例如：

```text
command not found
```

檢查：

```bash
command -v 工具名稱
```

這通常表示工具沒有安裝，或不在 PATH 中。先確認工具名稱和官方安裝方式，不要隨便執行網路上不明的安裝腳本。

## 問題 3：Permission denied

可能原因：

- 目前使用者沒有讀取或執行權限。
- 檔案沒有執行權限。
- 目錄不允許目前使用者進入。
- 系統安全政策限制操作。

檢查：

```bash
whoami
ls -l 檔案名稱
pwd
```

不要直接把所有權限改成 777。先弄清楚檔案屬於誰、為什麼需要該權限。

## 問題 4：apt update 失敗

先確認：

```bash
cat /etc/os-release
ip route
nslookup deb.debian.org
```

再閱讀 apt 顯示的完整錯誤。常見原因包括網路、DNS、套件來源設定或系統時間不正確。不要把陌生鏡像站或不明套件來源直接加入系統。

## 問題 5：VMware 虛擬機很慢

檢查：

- 宿主機剩餘記憶體和磁碟空間。
- VMware 分配給 Kali 的 CPU 和 RAM。
- 是否同時開啟太多虛擬機。
- 是否有快照和虛擬磁碟長期累積。
- Windows 工作管理員中的 CPU、記憶體和磁碟使用率。

不要只因為 Kali 慢就直接增加大量虛擬 CPU 或記憶體；先確認宿主機還有足夠資源。

## 問題 6：Nmap 沒有顯示開放連接埠

可能是本機沒有服務監聽、目標選錯、服務只監聽特定介面，或防火牆影響結果。

在自己的 Kali 中查看：

```bash
ss -tuln
```

先確認是否真的有服務在監聽，再理解掃描結果。沒有顯示開放連接埠不一定是工具故障。

## 問題 7：Wireshark 看不到想要的封包

確認：

- 選對網路介面。
- 開始擷取後才產生測試流量。
- 沒有套用錯誤的顯示篩選器。
- 權限和擷取設定允許觀察。
- 流量可能使用 TLS 加密，因此看不到明文內容。
