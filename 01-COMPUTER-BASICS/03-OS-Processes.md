# 01-03｜作業系統、程式、程序和執行緒

> 難度：初級至初中級｜建議時間：90–120 分鐘｜先修：01-01、01-02
>
> 本課會從 Windows 和 Kali 的日常操作出發，解釋作業系統如何管理程式、CPU、記憶體、檔案和設備。這些概念是後續學 Linux、日誌分析、惡意程式分析和事件應變的基礎。

## 二、作業系統是什麼？

作業系統（Operating System，OS）是管理電腦硬體資源，並為應用程式提供執行環境的系統軟體。

常見作業系統：
- Microsoft Windows：常見於個人電腦和企業桌面。
- Linux：廣泛用於伺服器、雲端、嵌入式設備和安全研究。
- macOS：Apple 電腦使用的作業系統。
- Android：以 Linux 核心為基礎的行動作業系統。
- iOS：Apple 行動裝置使用的作業系統。

Chrome、Word、Wireshark 和 Burp Suite 是應用程式，不是作業系統。

## 三、作業系統主要管理哪些事情？

### 1. 程序管理 Process Management

作業系統負責建立、排程、暫停和結束程序，分配 CPU 時間，並管理程序之間的隔離和通訊。

例子：你同時開啟 Chrome、記事本和 VMware，Windows 需要安排它們如何使用 CPU。

### 2. 記憶體管理 Memory Management

作業系統負責分配和回收記憶體，管理虛擬位址空間，並避免一般程序任意讀取其他程序的記憶體。

這種隔離是安全的重要基礎。如果任意一個普通應用程式都能讀取所有程序的記憶體，密碼、文件和其他敏感資料就很難受到保護。

### 3. 檔案系統管理 File System Management

作業系統透過檔案系統管理檔案名稱、目錄、資料位置、權限和中繼資料。

Windows 常見 NTFS；Linux 常見 ext4、XFS 等。不同檔案系統的特性不同，但都需要管理資料如何保存和讀取。

### 4. 設備管理 Device Management

鍵盤、滑鼠、顯示卡、網卡和儲存裝置需要透過驅動程式（Driver）與作業系統協作。

驅動程式讓作業系統能以標準方式使用硬體。驅動程式出錯可能導致設備無法工作、系統不穩或安全風險。

### 5. 使用者與權限管理

作業系統會識別使用者、群組和安全權限，決定誰能讀取檔案、安裝軟體、修改系統設定或啟動服務。

安全原則是：一般日常工作使用一般權限，只有確實需要時才提升權限。

## 四、程式、程序和執行緒的差別

這三個名詞非常重要，不能混為一談。

### 1. Program（程式）

程式通常指儲存在磁碟上的可執行檔、程式碼或應用程式。例如 Windows 中的 chrome.exe，或 Linux 中的某個可執行檔。

它可以存在於磁碟中，即使目前沒有執行。

### 2. Process（程序）

程序是程式啟動後，由作業系統管理的執行實例。程序通常具有自己的虛擬位址空間、程序識別碼、資源和安全權限。

同一個程式可以被啟動多次，產生多個程序；一個應用程式也可能使用多個程序。因此「一個程式等於一個程序」並不正確。

### 3. Thread（執行緒）

執行緒是程序內部的執行流程。一個程序可以只有一個執行緒，也可以有多個執行緒。

例如瀏覽器可能把分頁、網路工作、畫面繪製和其他工作分配到不同程序或執行緒。這種設計可以改善穩定性和資源管理，但實際架構依瀏覽器版本而異。

### 4. 三者關係圖

    磁碟上的程式檔
          │ 啟動
          ▼
        程序 A
       ├─ 執行緒 1
       ├─ 執行緒 2
       └─ 執行緒 3

    同一程式也可能再啟動程序 B
       ├─ 執行緒 1
       └─ 執行緒 2

## 五、PID 是什麼？

PID（Process ID，程序識別碼）是作業系統用來識別程序的數字。

在 Windows 工作管理員的「詳細資料」頁可以看到 PID。在 Linux 中可以用 ps 等命令查看。

注意：
- PID 可能在程序結束後被重新使用。
- 不要把 PID 當成永久不變的設備識別碼。
- 單憑 PID 數字無法判斷程序是否安全。
- 需要結合程序名稱、執行路徑、簽章、啟動時間、父程序和網路活動等資訊判斷。

## 六、使用者模式和核心模式

### 1. User Mode（使用者模式）

一般應用程式通常在使用者模式執行。它受到作業系統限制，不能任意執行所有硬體操作或讀取所有核心資料。

例如 Chrome、記事本和一般文字編輯器通常在使用者模式工作。

### 2. Kernel Mode（核心模式）

作業系統核心和部分核心級驅動程式在核心模式執行，能存取更高權限的系統資源。

核心模式程式出錯可能造成整個系統不穩定，甚至藍色畫面。

### 3. 為什麼要分開？

權限分層能降低一般應用程式出錯或遭到利用時對整個系統造成的影響。這不是絕對安全，但能建立重要的隔離邊界。

## 七、Windows 實驗：查看程序和 PID

### 步驟 A：打開工作管理員

1. 按 Ctrl + Shift + Esc。
2. 選擇「處理程序」。
3. 找到 Chrome（若正在執行）。
4. 觀察 CPU、記憶體、磁碟和網路欄位。

### 步驟 B：查看 PID

1. 在工作管理員切換到「詳細資料」。
2. 找到 chrome.exe 或其他你認識的程序。
3. 觀察 PID 欄位。
4. 記錄程序名稱和 PID。

不要為了實驗而結束不認識的程序。

### 步驟 C：使用 PowerShell 查看程序

開啟一般 PowerShell（不必以系統管理員身分執行）：

    Get-Process | Select-Object -First 10 ProcessName, Id, CPU, WorkingSet

參數解釋：

- Get-Process：取得本機程序資訊。
- 管線符號 |：把左側命令輸出傳給右側命令。
- Select-Object：選擇要顯示的欄位。
- -First 10：只顯示前十筆。
- ProcessName：程序名稱。
- Id：程序識別碼。
- CPU：程序累積使用 CPU 時間的相關數值，不是即時 CPU 百分比。
- WorkingSet：程序目前的工作集記憶體量。

如果結果和工作管理員的即時 CPU 百分比不同，這是因為兩者顯示的指標並不完全相同。

## 八、Kali Linux 實驗：查看程序

在 Kali 終端機輸入：

### 1. 查看目前使用者

    whoami

用途：顯示目前登入的使用者名稱。

### 2. 查看目前終端機相關程序

    ps

用途：顯示目前終端機工作階段中相關的程序。

### 3. 查看較完整的程序清單

    ps aux

參數概念：
- a：顯示與終端機相關的其他使用者程序。
- u：使用較詳細的使用者導向格式。
- x：也顯示沒有控制終端機的程序。

不同 Linux 發行版和 ps 實作的細節可能略有差異。觀察輸出中的 USER、PID、%CPU、%MEM、STAT、COMMAND 等欄位。

### 4. 即時查看程序

    top

top 會持續更新系統和程序資訊。按 q 離開。

## 九、服務 Service 和一般程序有什麼不同？

服務通常是為其他程式或使用者提供功能的背景程序，例如網路管理、時間同步或遠端管理服務。

Linux 常使用 systemd 管理服務；Windows 有自己的 Service Control Manager。

Kali 可查看某個已知服務的狀態：

    systemctl status NetworkManager

如果顯示服務不存在，先確認系統是否安裝該服務，以及名稱是否正確。不要因為一個服務名稱不存在就判定系統中毒或損壞。

## 十、為什麼不能隨意結束陌生程序？

程序可能是：
- Windows 或 Linux 的核心支援程序。
- 驅動程式或硬體管理程序。
- 防毒、防火牆或更新服務。
- 你正在使用的應用程式。
- 惡意程式或不必要的軟體。

正確排查順序：

1. 記錄程序名稱和 PID。
2. 查明執行路徑和發行者。
3. 查看數位簽章（適用時）。
4. 觀察它何時啟動、是否持續消耗資源。
5. 使用可信的安全工具檢查。
6. 有充分理由後再決定是否隔離或結束。

不要因為網路文章說某個程序「看起來陌生」就刪除系統檔案。

## 十一、常見錯誤

**問題 1：PowerShell 顯示 Get-Process 找不到。**

確認目前開啟的是 Windows PowerShell 或 PowerShell，而不是其他不支援該命令的終端環境。

**問題 2：Kali 顯示 systemctl 找不到。**

先確認系統環境是否使用 systemd。容器、精簡環境或某些子系統可能沒有 systemd 作為 PID 1。

**問題 3：ps aux 顯示很多程序，看不懂。**

先不要逐個研究。只挑選自己認識的 Chrome、終端機或 NetworkManager，理解欄位即可。
