# 01-04｜Windows 工作管理員完整實驗：從觀察到初步診斷

> 難度：初級｜建議時間：60–90 分鐘｜先修：01-01 至 01-03
>
> 這是一份動手實驗，不是單純閱讀。請按照步驟操作，把自己電腦實際顯示的數據填入紀錄表。不要為了得到特定數字而修改系統設定。

## 一、實驗目標

完成後，你應該能夠：

1. 開啟 Windows 工作管理員並找到主要分頁。
2. 觀察 CPU、記憶體、磁碟、網路和 GPU。
3. 從程序清單找出資源使用較高的應用程式。
4. 了解工作管理員顯示的是觀察資料，不是自動診斷結論。
5. 用簡單步驟排查「電腦變慢」的可能原因。

## 二、實驗安全注意事項

- 只查看資訊，不修改服務、啟動項或系統設定。
- 不要結束不認識的 Windows 系統程序。
- 不要在更新、檔案複製或重要工作期間強制關機。
- 如果電腦正在異常發熱、出現硬體異音或頻繁藍色畫面，先停止負載測試。
- 分享截圖前，遮蔽使用者名稱、裝置名稱和其他私人資訊。

## 三、第一部分：打開工作管理員

### 方法 A：鍵盤快捷鍵

同時按下：

    Ctrl + Shift + Esc

這是最直接的方式。

### 方法 B：工作列

在 Windows 工作列空白處按滑鼠右鍵，選擇「工作管理員」（不同 Windows 版本的選單可能略有不同）。

### 如果看到簡化視窗

點擊「更多詳細資料」，才能看到完整分頁。

## 四、第二部分：認識「處理程序」分頁

這個頁面列出目前正在執行的應用程式和背景程序。

常見欄位：

| 欄位 | 意義 | 觀察重點 |
|---|---|---|
| 名稱 | 程序或應用程式名稱 | 是否認識 |
| CPU | CPU 使用比例 | 是否有程序持續偏高 |
| 記憶體 | 程序使用的記憶體 | 哪些程式佔用較多 |
| 磁碟 | 程序目前的磁碟活動 | 是否有大量讀寫 |
| 網路 | 程序網路活動 | 是否正在下載或上傳 |
| GPU | 圖形處理器使用情況 | 是否有圖形工作 |

### 動手操作

1. 點擊 CPU 欄位標題，讓使用量較高的程序排在前面。
2. 記錄前兩個你認識的程序。
3. 點擊記憶體欄位標題，再記錄前兩個程序。
4. 點擊磁碟欄位標題，觀察是否有程序正在大量讀寫。
5. 不要點「結束工作」，這次只觀察。

### 怎樣判斷？

單一時間點的高使用率不一定是問題。請觀察：
- 是否持續數分鐘？
- 是否剛好在更新、下載或播放影片？
- 電腦是否真的卡頓？
- 是否有不認識的程序持續大量使用資源？

## 五、第三部分：CPU 效能頁

1. 點選左側「效能」。
2. 點選「CPU」。
3. 找到處理器名稱。
4. 查看使用率、速度、核心和邏輯處理器數量。

### 欄位解釋

- 使用率：目前 CPU 忙碌程度的估算。
- 速度：目前運作頻率，可能隨負載和電源管理改變。
- 核心：實體 CPU 核心數。
- 邏輯處理器：作業系統可排程的邏輯處理資源數量。
- 執行時間：系統自開機以來的運行時間。

### 實驗觀察

先保持電腦閒置約 30 秒，記錄 CPU 使用率；再開啟一個平常使用的網站，等待載入，觀察使用率變化。

不要刻意開啟大量影片或分頁來讓 CPU 滿載。

## 六、第四部分：記憶體效能頁

1. 點選「記憶體」。
2. 記錄已安裝容量。
3. 記錄使用中、可用和已提交的數值。
4. 留意速度、已使用插槽等資訊（若有顯示）。

### 如何理解數字？

- 使用中：目前被系統和程式使用的實體記憶體。
- 可用：目前可以分配給新工作使用的記憶體，包含可回收部分。
- 已提交：系統承諾提供的虛擬記憶體量，不等於 RAM 的實際使用量。
- 快取：用來加速資料存取的記憶體，部分可在需要時回收。

如果記憶體數字較高，不要立刻判斷電腦中毒。先看是哪個程序使用，以及是否有實際卡頓。

## 七、第五部分：磁碟效能頁

1. 點選「磁碟 0」或對應磁碟。
2. 查看磁碟型號和容量。
3. 觀察活動時間。
4. 查看讀取和寫入速度。

### 重要概念

活動時間高表示磁碟正忙於處理 I/O，但不一定代表資料傳輸速度很高。大量小型隨機讀寫也可能讓活動時間升高。

### 常見原因

- Windows Update 正在安裝更新。
- 防毒軟體正在掃描。
- Chrome 或其他程式正在讀寫快取。
- VMware 正在讀寫虛擬磁碟。
- 系統正在使用分頁檔。

請結合「處理程序」分頁找出可能的來源。

## 八、第六部分：網路效能頁

1. 點選 Wi-Fi 或乙太網路。
2. 觀察傳送和接收速度。
3. 開啟一般網站，再觀察數值是否變化。
4. 停止載入後，觀察流量是否下降。

注意：網路速度欄位會受到網路活動影響。沒有流量不代表網路故障；高流量也不一定代表遭到攻擊。

## 九、第七部分：GPU 效能頁

如果電腦有 GPU，工作管理員可能顯示 3D、Copy、Video Decode 等引擎。

- 3D：常與圖形繪製相關。
- Video Decode：影片解碼工作。
- Copy：資料複製工作。
- Dedicated GPU Memory：獨立顯示記憶體。
- Shared GPU Memory：系統記憶體中可供 GPU 使用的部分。

不同顯示卡和驅動程式會顯示不同資訊。

## 十、第八部分：查看程序 PID

1. 切換到「詳細資料」。
2. 找到一個自己認識的程序，例如記事本或 Chrome。
3. 記錄名稱和 PID。
4. 回到「處理程序」頁，確認同一應用程式可能對應多個程序。

這個練習用來理解 PID，不需要結束程序。

## 十二、故障排查案例

### 案例 A：電腦很卡，但 CPU 使用率很低

可能原因：
- 磁碟正在等待大量 I/O。
- 記憶體不足，系統頻繁分頁。
- 網路服務正在等待回應。
- 某個程式本身卡住或等待其他資源。

排查順序：
1. 看記憶體是否接近滿載。
2. 看磁碟活動時間和讀寫速度。
3. 在處理程序頁依磁碟排序。
4. 檢查是否正在更新或同步。
5. 記錄現象，不要立即修改系統設定。

### 案例 B：Chrome 使用很多記憶體

可能原因：
- 開啟的分頁較多。
- 網頁內容複雜。
- 擴充功能使用資源。
- 瀏覽器以多程序架構運作。

排查：
1. 先記錄 Chrome 分頁數量。
2. 關閉不需要的分頁。
3. 觀察記憶體使用是否下降。
4. 如有需要，使用 Chrome 工作管理員查看分頁和擴充功能的資源使用。

### 案例 C：啟動 Kali 後 Windows 變慢

可能原因：
- Kali 分配的 RAM 過多。
- 虛擬 CPU 配置不合理。
- 虛擬磁碟大量讀寫。
- Windows 同時運行 Chrome、更新或其他程式。

排查：
1. 先記錄 Windows 記憶體使用量。
2. 在 VMware 查看 Kali 分配的 RAM 和 CPU。
3. 正常關閉 Kali。
4. 比較關閉前後 Windows 的資源使用。
5. 下一個模組再學習如何安全調整虛擬機配置。

### 案例 D：磁碟活動時間長時間很高

排查：
1. 查看處理程序頁的磁碟欄位。
2. 找出讀寫量較高的程序。
3. 查看 Windows Update 是否正在工作。
4. 查看是否有備份、同步或防毒掃描。
5. 若伴隨磁碟錯誤、異常聲響或頻繁當機，停止不必要的操作並備份重要資料，再進一步診斷。

## 十三、本課測驗

1. 工作管理員「處理程序」和「效能」頁有什麼差別？
2. CPU 使用率高，是否必然代表電腦故障？
3. 記憶體「已提交」和「使用中」有何不同？
4. 為什麼磁碟活動時間 100% 不代表讀寫速度一定很快？
5. Chrome 為什麼可能顯示多個程序？
6. Kali 虛擬機為什麼會影響 Windows 的記憶體？
7. 電腦卡頓時，為什麼應先觀察而不是隨意結束程序？
