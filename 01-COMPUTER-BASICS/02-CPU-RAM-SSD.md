# 01-02｜CPU、RAM、SSD：電腦為什麼會快、會慢？

> 難度：初級至初中級｜建議時間：90 分鐘｜先修：01-01 電腦的基本組成
>
> 本課會把三個最重要的資源分開講清楚。不要只記「CPU 是大腦、RAM 是桌面、SSD 是倉庫」；你還要能看懂 Windows 顯示的數據，知道效能瓶頸可能出在哪裡。

## 一、本課學習成果

完成後，你應該能夠：

1. 說明 CPU 的核心、執行緒、時脈和快取是什麼。
2. 解釋 RAM 為何需要持續供電，以及虛擬記憶體的基本概念。
3. 分辨 SSD 和 HDD，理解 SSD 讀寫資料的大致方式。
4. 理解程式從 SSD 載入 RAM，再由 CPU 執行的基本流程。
5. 用工作管理員初步判斷 CPU、記憶體或磁碟是否可能成為瓶頸。

## 二、CPU：負責執行指令

### 1. CPU 到底做什麼？

CPU（Central Processing Unit，中央處理器）會從程式和系統提供的指令中取出要執行的操作，進行解碼和執行，並讀取或寫入需要的資料。

簡化來說，CPU 會反覆完成以下工作：

1. 取得指令。
2. 解讀指令要做什麼。
3. 取得所需資料。
4. 執行運算或控制操作。
5. 將結果寫回暫存器或記憶體。
6. 繼續處理下一條指令。

這個模型稱為「取指、解碼、執行」的簡化概念。現代 CPU 會使用管線、分支預測、亂序執行和多層快取等技術，因此真實內部流程遠比這個模型複雜。

### 2. 核心 Core

CPU 核心是執行指令的運算單元。多核心 CPU 可以在同一時間處理更多執行工作，但不代表所有程式都會自動變快。

例如：
- 一個程式只使用單一主要執行緒時，增加核心數不一定讓它按比例加速。
- 多個程式同時工作時，多核心通常有助於分配工作。
- 某些工作受記憶體或磁碟速度限制，CPU 核心再多也無法完全解決。

### 3. 執行緒 Thread

執行緒是程序內部的執行流程。程式可以建立多個執行緒，讓不同工作有機會並行或交錯執行。

要區分：
- 軟體執行緒：作業系統排程的執行單位。
- 硬體執行緒：CPU 提供的邏輯執行資源，例如 Intel Hyper-Threading 或其他 SMT 技術。

工作管理員顯示的「邏輯處理器」通常與硬體執行緒有關，不一定等於實體核心數。

### 4. 時脈 Clock Speed

時脈以 Hz 或 GHz 表示，代表時鐘週期的頻率。較高時脈在其他條件相近時可能帶來較高效能，但不能只憑 GHz 比較兩顆不同架構的 CPU。

影響效能的因素還包括：
- 每個時鐘週期能完成多少工作。
- 核心和執行緒數量。
- 快取容量和記憶體延遲。
- 功耗、散熱和工作負載。
- 指令集和軟體是否能有效利用硬體。

### 5. CPU 快取 Cache

CPU 快取是靠近處理器、速度快但容量較小的記憶體。它保存 CPU 近期或可能再次使用的資料，減少每次都去 RAM 取資料的等待時間。

常見層級：
- L1 Cache：通常最靠近核心，容量較小、速度很快。
- L2 Cache：容量通常比 L1 大。
- L3 Cache：常由多個核心共享，具體設計依 CPU 而不同。

快取命中（Cache Hit）表示需要的資料在快取中；快取未命中（Cache Miss）表示需要到更遠的記憶體層級取得資料，通常會增加等待時間。

初學階段只需理解「CPU 快取用來降低等待資料的時間」，不必背各代 CPU 的快取容量。

## 三、RAM：程式執行時使用的工作空間

### 1. RAM 是什麼？

RAM（Random Access Memory，隨機存取記憶體）用來保存系統和程式目前正在使用的資料。它的主要特點是存取速度通常比 SSD 快很多，但斷電後資料不會像 SSD 一樣持續保存。

當你開啟 Chrome：
- Windows 會建立或使用相關程序。
- 程式碼和資料會被載入或映射到記憶體。
- 網頁、分頁、圖片和擴充功能會使用記憶體。
- 作業系統也會使用記憶體管理核心、驅動程式和快取。

### 2. RAM 和 SSD 為什麼不能互相取代？

| 比較 | RAM | SSD |
|---|---|---|
| 主要用途 | 執行中的工作資料 | 長期保存檔案 |
| 斷電後 | 一般不保留資料 | 保留資料 |
| 存取特性 | 延遲低、速度高 | 比 RAM 慢，但容量通常更大 |
| 常見內容 | 程序資料、核心資料、快取 | Windows、程式、照片、虛擬機檔案 |
| 容量成本 | 每 GB 通常較高 | 每 GB 通常較低 |

所以，不能因為 SSD 容量很大，就認為它可以完全取代 RAM。

### 3. 什麼是虛擬記憶體 Virtual Memory？

虛擬記憶體是作業系統提供給程序的一種記憶體管理抽象。每個程序通常看到自己的虛擬位址空間，作業系統和硬體記憶體管理單元會把虛擬位址映射到實體記憶體或其他後端儲存。

Windows 也使用分頁檔（Page File）支援系統的記憶體管理。當實體 RAM 壓力增加時，部分記憶體頁面可能被移出 RAM；需要時再載入。這個過程可能造成額外磁碟 I/O 和效能下降。

重要區分：
- 虛擬記憶體不是「把 SSD 變成同樣快的 RAM」。
- 分頁檔不是 RAM 的完整替代品。
- 記憶體使用率高不一定代表系統故障。
- 不應為了追求效能而隨意關閉 Windows 分頁檔。

### 4. VMware 為什麼會消耗大量 RAM？

你在 Windows 上執行 VMware，再於虛擬機裡啟動 Kali，至少有兩層系統同時需要資源：

- Windows 宿主機需要 RAM。
- VMware 程序需要 RAM 管理虛擬機。
- Kali 客體系統需要 RAM。
- Kali 裡的瀏覽器、終端機和工具也會使用 RAM。

如果給 Kali 分配太多記憶體，Windows 和 Chrome 可能缺少可用資源；分配太少，Kali 可能變慢或無法順利運行。合理配置要依實際總記憶體、工作負載和虛擬機數量決定。

## 四、SSD：長期保存資料的裝置

### 1. SSD 和 HDD 的差異

HDD（Hard Disk Drive，傳統機械硬碟）使用旋轉磁碟和讀寫磁頭保存資料。SSD（Solid State Drive，固態硬碟）使用快閃記憶體晶片保存資料，沒有傳統 HDD 的旋轉碟片和移動磁頭。

一般而言：
- SSD 的隨機存取延遲通常較低。
- HDD 在相同預算下可能提供較大的容量。
- SSD 仍有寫入壽命和控制器等限制。
- 不論 SSD 或 HDD，都可能因故障、誤刪或惡意程式而失去資料，因此仍要備份。

### 2. SSD 的基本工作方式

SSD 內部通常包含：
- NAND Flash：保存資料的快閃記憶體。
- Controller：控制器，負責管理讀寫和記憶體配置。
- Firmware：控制器執行的韌體。
- Cache / Buffer：依裝置設計提供暫存或加速功能。

SSD 控制器會處理邏輯位址與實際 NAND 位置之間的映射，並執行磨損平均（Wear Leveling）、垃圾回收（Garbage Collection）和錯誤校正等工作。

### 3. 為什麼 SSD 也可能變慢？

常見原因包括：
- 磁碟空間接近用盡。
- 大量小檔案讀寫。
- 背景更新、同步或防毒掃描。
- 虛擬機同時讀寫大量資料。
- SSD 溫度過高或控制器降速。
- 磁碟或檔案系統出現錯誤。

不能只憑「磁碟活動時間 100%」就判定 SSD 壞掉。要結合讀寫速度、程序、事件記錄和裝置健康資訊判斷。

## 五、三者如何合作：以啟動 Chrome 為例

1. Chrome 安裝檔和程式資料原本保存在 SSD。
2. 你點擊 Chrome 圖示後，Windows 啟動相關程序。
3. 作業系統將程式所需的部分資料載入或映射到 RAM。
4. CPU 從記憶體取得指令和資料並執行。
5. CPU 快取保存部分近期使用的資料。
6. Chrome 需要網頁時，網卡負責收發網路封包。
7. 網頁內容、快取或下載檔案可能再寫入 SSD。

簡化圖：

    SSD（保存程式和檔案）
              ↓ 載入／映射
    RAM（執行期間使用的資料）
              ↕
    CPU（執行指令，使用快取）
              ↓
    網路、GPU、螢幕和其他設備

## 六、Windows 效能觀察實驗

### 實驗目的

觀察 CPU、RAM 和磁碟在不同工作負載下的變化，練習用證據判斷瓶頸。

### 實驗準備

- 不需要安裝任何第三方軟體。
- 先保存正在編輯的文件。
- 不要為了測試而執行不明程式或壓力測試工具。
- 如果電腦正在更新或執行重要工作，先不要做實驗。

### 實驗 A：記錄閒置狀態

1. 按 Ctrl + Shift + Esc 開啟工作管理員。
2. 選擇「效能」。
3. 等待約一分鐘，觀察 CPU、記憶體和磁碟。
4. 記錄大致數值，不必追求精確到每一秒。

### 實驗 B：開啟 Chrome

1. 開啟 Chrome。
2. 開啟一個平常使用的網站。
3. 等頁面載入完成。
4. 觀察 CPU、記憶體和磁碟是否變化。
5. 回到「處理程序」，點選記憶體欄位排序，觀察 Chrome 的資源使用。

### 實驗 C：觀察 VMware（若平常有使用）

1. 確認 Windows 沒有正在進行重要更新。
2. 啟動 VMware 和自己的 Kali 虛擬機。
3. 觀察 Windows 記憶體使用量和 VMware 程序。
4. 如果系統明顯變慢，先正常關閉 Kali 虛擬機，不要直接強制關機。
5. 記錄虛擬機分配的記憶體容量。

### 實驗紀錄

| 狀態 | CPU 使用率 | RAM 使用量 | 磁碟活動 | 備註 |
|---|---|---|---|---|
| 閒置 | | | | |
| Chrome 開啟 | | | | |
| Chrome 多分頁 | | | | |
| VMware/Kali 運行 | | | | |

## 七、如何初步判斷效能瓶頸？

| 觀察現象 | 可能原因 | 下一步檢查 |
|---|---|---|
| CPU 長時間很高 | 程式大量運算、背景工作或異常程序 | 按 CPU 排序，檢查程序名稱 |
| 記憶體接近滿載且系統卡頓 | 同時開啟太多程式、VM 配置過高 | 按記憶體排序，檢查 VM 配置 |
| 磁碟活動很高、回應慢 | 更新、同步、分頁或大量讀寫 | 按磁碟排序，檢查讀寫程序 |
| CPU 不高但程式仍慢 | 網路、磁碟、鎖定或程式本身等待 | 觀察磁碟、網路和應用程式狀態 |
| VMware 啟動後整機變慢 | 宿主機資源不足或 VM 配置不合理 | 檢查 Windows 和 Guest 資源分配 |

這些只是排查方向，不是單一現象對應唯一故障。

## 八、常見問題

**Q1：記憶體使用率 80% 是不是一定有問題？**

不是。Windows 會利用空閒記憶體作快取。應同時觀察可用記憶體、已提交量、系統是否卡頓，以及哪個程序使用資源。

**Q2：CPU 使用率 100% 是不是代表 CPU 壞了？**

不是。CPU 正在滿載工作可能是正常現象。若長時間高負載並伴隨異常溫度、降頻或系統錯誤，才需要進一步檢查。

**Q3：SSD 空間還很多，為什麼讀寫仍然慢？**

空間只是其中一個因素。背景 I/O、裝置溫度、控制器、介面、驅動程式和磁碟健康狀態都可能影響速度。

**Q4：可以把分頁檔關掉來提高速度嗎？**

不建議。分頁檔是 Windows 記憶體管理的一部分。關閉後可能導致某些程式無法正常配置記憶體，並不保證效能提升。
